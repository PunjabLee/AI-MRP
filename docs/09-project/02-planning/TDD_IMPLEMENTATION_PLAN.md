## 一、概述

### 1.1 目的

本文档定义AI-MRP项目采用**测试驱动开发 (Test-Driven Development, TDD)** 的实施方法论，确保开发过程以测试为核心，代码质量可控。

### 1.2 TDD核心原则

```
红 → 绿 → 重构

1. 编写一个失败的测试 (红)
2. 编写最少量代码使测试通过 (绿)
3. 重构代码 (重构)
```

### 1.3 预期输入/输出对

| 阶段 | 输入 | 输出 |
|------|------|------|
| 需求分析 | PRD文档、功能设计、业务流程 | 测试用例清单 |
| 测试编写 | 测试用例清单 | 失败的测试用例 |
| 开发实现 | 失败的测试用例 | 通过的测试用例 |
| 重构优化 | 通过的测试用例 | 重构后的代码 |

## 二、测试分层架构

### 2.1 测试金字塔

```
           /\
          /  \
         / E2E \        ← 端到端测试 (10%)
        /--------\
       /  集成  \       ← 服务集成测试 (20%)
      /------------\
     /   单元测试  \     ← 单元测试 (70%)
    /--------------\
```

### 2.2 测试类型定义

| 层级 | 范围 | 工具 |
|------|------|------|
| 单元测试 | 单个类/方法 | JUnit 5, Mockito |
| 集成测试 | 多模块交互 | Spring Boot Test |
| E2E测试 | 完整业务流程 | Postman/Newman |

## 四、TDD开发流程

### 4.1 流程步骤

```
┌─────────────┐
│ 1. 分析需求  │  ← 阅读PRD/设计文档
└──────┬──────┘
       ▼
┌─────────────┐
│ 2. 编写测试  │  ← 编写失败的测试 (红)
└──────┬──────┘
       ▼
┌─────────────┐
│ 3. 运行测试  │  ← 确认测试失败
└──────┬──────┘
       ▼
┌─────────────┐
│ 4. 实现代码  │  ← 最少量代码使测试通过 (绿)
└──────┬──────┘
       ▼
┌─────────────┐
│ 5. 运行测试  │  ← 确认测试通过
└──────┬──────┘
       ▼
┌─────────────┐
│ 6. 重构代码  │  ← 保持测试通过前提下优化
└──────┬──────┘
       ▼
┌─────────────┐
│ 7. 提交代码  │  ← 测试全部通过
└─────────────┘
```

### 4.2 每个模块的开发顺序

```
优先级排序:

P0 (核心):
1. 需求管理 → 2. BOM管理 → 3. 库存管理 → 4. MRP计算

P1 (业务):
5. 采购管理 → 6. 生产管理

P2 (智能):
7. LLM理解 → 8. OR求解 → 9. 预测分析

P3 (增值):
10. 异常诊断 → 11. 风险预警 → 12. 影响分析
```
