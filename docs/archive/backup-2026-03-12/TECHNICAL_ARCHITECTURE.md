## 二、技术栈选型

### 2.1 后端技术栈

| 层级 | 技术 | 版本 | 说明 |
|------|------|------|------|
| **语言** | Java | 17+ | 主后端服务 |
| **框架** | Spring Boot | 3.2+ | 生态丰富 |
| **微服务** | Spring Cloud | 2023+ | Gateway + Nacos |
| **持久层** | MyBatis-Plus | 3.5+ | 效率优先 |
| **数据库** | **PostgreSQL** | **15+** | 主数据 + 交易 |
| **缓存** | Redis | 7.0 | 热点数据 + 会话 |
| **消息队列** | RabbitMQ | 3.12+ | 异步解耦 |
| **文件存储** | MinIO | latest | 图片/附件 |
| **搜索** | Elasticsearch | 8.x | 日志/分析 |

### 2.2 前端技术栈

| 层级 | 技术 | 版本 | 说明 |
|------|------|------|------|
| **框架** | React | 18.2+ | 主流 |
| **语言** | TypeScript | 5.4+ | 类型安全 |
| **构建** | Vite | 5.x | 快速 |
| **状态** | Zustand | 4.5+ | 轻量 |
| **UI** | Ant Design | 5.x | 企业组件 |
| **图表** | ECharts | 5.x | 可视化 |
| **桌面** | Electron | 28.x | 桌面端 |
| **微前端** | qiankun | 2.x | Web 版 |

### 2.3 AI/算法技术栈（Python 微服务）

> **架构说明**：AI 能力独立为 Python 微服务，与 Java 主服务通过 API 通信

| 层级 | 技术 | 说明 |
|------|------|------|
| **运行时** | Python 3.11 | AI 领域首选 |
| **AI 框架** | **LangChain** | Agent 编排 + RAG |
| **LLM** | OpenAI API / DeepSeek | 自然语言理解 |
| **本地 LLM** | Ollama | 可选私有部署 |
| **OR 求解** | **Google OR-Tools** | 生产排程优化 |
| **时序预测** | Prophet / Statsmodels | 需求预测 |
| **向量库** | Qdrant | 知识库检索 |
| **服务框架** | FastAPI | Python 微服务 |

## 八、技术选型理由

### 8.1 为什么选择 Spring Boot + Java？

| 理由 | 说明 |
|------|------|
| **企业级稳定性** | 经过大规模生产验证 |
| **生态丰富** | Spring Cloud 全家桶 |
| **人才充足** | 招聘和维护成本低 |
| **性能足够** | 对话式响应足够 |

### 8.2 为什么选择 React + TypeScript？

| 理由 | 说明 |
|------|------|
| **组件化** | 适合复杂业务表单 |
| **类型安全** | TS 减少运行时错误 |
| **状态管理** | Zustand 轻量易用 |
| **社区活跃** | 生态丰富 |

### 8.3 为什么选择 Python + LangChain？

| 理由 | 说明 |
|------|------|
| **AI 生态** | Python 是 AI 领域事实标准 |
| **LangChain** | Agent 编排、RAG、LLM 调用最佳框架 |
| **OR-Tools** | Google 官方 Python 绑定，丰富求解器 |
| **Prophet** | Facebook 开源时序预测，集成方便 |
| **解耦** | AI 服务独立，不影响主业务稳定性 |

### 8.4 为什么选择 PostgreSQL？

| 理由 | 说明 |
|------|------|
| **功能强大** | JSON、数组、全文搜索等高级特性 |
| **性能优秀** | 索引优化、查询 planner 优秀 |
| **高可用成熟** | 流复制、Patroni 方案成熟 |
| **生态丰富** | 开源扩展（如 PostGIS、Citus） |
